# Дизайн доработок: персональная лента и агентный разбор новостей

Дата: 2026-10-23. Статус: согласовано с капитаном команды (делегировано: «сделай всё, что нужно для призового места»).

## Цель

Пройти полный сценарий кейса Альфа-Банка: вход в интернет-банк → выбор крупного клиента и роли пользователя → персональная лента новостей → разбор события с рисками, возможностями, действиями, позицией банка и источниками → уточняющий вопрос или другой разрез. Сменил клиента или роль — лента перестроилась.

Критерии жюри, которые закрывает дизайн: 01–06 (контекст, глубина, позиция банка, источники, новые новости, сквозной сценарий), 07 (масштабирование), 08 (метрики), 10 (уточнения, разрезы, первоисточник), 11 (агентная логика с корректировкой), 12 (трассировка). Критерий 09 (точка входа на главном экране) закрывает фронтенд.

## Ограничения

- Существующий C++20 бэкенд не переписываем, расширяем. Без новых сторонних библиотек: только libcurl и стандартная библиотека.
- Только 6 разрешённых моделей и 2 разрешённых шлюза. Общий бюджет 500 руб. в день: дорогие вызовы только по запросу пользователя, кэш результатов, счётчик токенов с дневным лимитом.
- Без базы данных: состояние в JSON-файлах каталога `work/`.
- Ключ модели только в окружении бэкенда, никогда во фронте и в репозитории.

## Компоненты

1. **Клиенты** (`DataStore::list`). Фильтры: поиск по ID/ОКВЭД/отрасли, отрасль, регион, минимальная выручка (по умолчанию 15 млрд руб.), пагинация. Фасеты: топ отраслей и регионов среди крупных клиентов.
2. **Новости** (`news_store`, `rss`). Хранилище новостей с дедупликацией (совпадение нормализованного заголовка или пересечение слов ≥ 0,6 — одна карточка, несколько ссылок). Источники: демо-набор `data/news/seed.json` (реальные новости с короткими пересказами и ссылками) + RSS разрешённых изданий по расписанию (`ALFA_NEWS_REFRESH_MINUTES`, 0 — выключено). Загрузка RSS через ту же защиту от SSRF, что и парсер страниц. Классификация по правилам (типы событий, отрасли, валюты, сырьё).
3. **Лента** (`feed`). Оценка = релевантность для компании (правила автора + контрагенты + роль) × свежесть. К каждой карточке: «почему вам» на правилах и подсказка, какой материал Альфа-Банка относится к теме (BM25). Без вызовов модели — лента бесплатная и мгновенная.
4. **Роли**: собственник, гендиректор, финдиректор, казначей, главный бухгалтер. Роль меняет веса категорий событий в ленте и фокус разбора.
5. **Агент** (`InsightAgent::analyze`). Цикл:
   1. `plan` — модель (быстрая) выбирает поисковые запросы по аналитике банка и нужные инструменты; без модели — детерминированный план.
   2. `tools` — профиль компании, контрагенты по платежам с их отраслями, поиск по аналитике по каждому запросу, связанные новости из ленты.
   3. `draft` — основная модель пишет разбор в JSON-схеме с evidence_ids.
   4. `verify` — программная проверка (у каждого утверждения есть источник; позиция банка ссылается на A-источник; числа из разбора встречаются в источниках) + модель-рецензент возвращает список проблем и недостающих запросов.
   5. `revise` — если проблемы есть: дополнительный поиск по новым запросам и переписывание (не больше одного дополнительного круга, при исчерпании бюджета — честная пометка).
   Каждый шаг пишется в `agent_trace` с входом, решением и результатом.
6. **Маршрутизация моделей**: `ALFA_LLM_MODEL_FAST` (по умолчанию Gemma 4 26B) для плана и уточнений, `ALFA_LLM_MODEL` (DeepSeek-V4.1-Flash) для разбора, `ALFA_LLM_MODEL_REVIEW` (GLM-5.3-Flash) для проверки. Учёт токенов из ответа шлюза, дневной лимит `ALFA_LLM_DAILY_TOKEN_LIMIT`.
7. **Кэш разборов**: ключ (компания, новость, роль). Повторное открытие бесплатно.
8. **Предложения банка**: правила по пробелам в продуктах (валюта и ВЭД без ВЭД-продуктов → валютный контроль и хеджирование; рост ставок и кредиты → рефинансирование и фиксированная ставка; логистика → факторинг; спрос и выручка → депозиты для свободной ликвидности). Помечены как реклама банка, отдельно от аналитики.
9. **Уточнения и разрезы**: свободный вопрос или готовый разрез (`risks`, `counterparties`, `treasury`, `scenarios`, `sources`).
10. **Обратная связь и метрики**: «полезно / не полезно» с причиной; метрики качества (доля полезных, доля подтверждённых утверждений, частота повторного поиска, доля разборов моделью, расход токенов, задержка).
11. **Раздача фронтенда**: каталог `ALFA_STATIC_DIR` по корню, CORS для локальной разработки через `ALFA_CORS_ORIGIN`.

## Новые маршруты API

| Маршрут | Назначение |
|---|---|
| `GET /api/v1/clients` | Список крупных клиентов с фильтрами и пагинацией |
| `GET /api/v1/clients/facets` | Отрасли и регионы для фильтров |
| `GET /api/v1/roles` | Роли пользователей |
| `GET /api/v1/news` | Новости в хранилище |
| `POST /api/v1/news/refresh` | Принудительный сбор RSS |
| `GET /api/v1/companies/{id}/feed?role=` | Персональная лента |
| `POST /api/v1/insights` | Разбор: `news_id` или `url` или `text`, плюс `role` |
| `POST /api/v1/insights/{id}/questions` | Вопрос или разрез (`lens`) |
| `POST /api/v1/feedback` | Оценка разбора |
| `GET /api/v1/metrics` | Метрики качества и расход |

## Ошибки и неполные данные

Пустые поля компании остаются «неизвестно». Нет модели или исчерпан бюджет → детерминированный разбор с пометкой метода. Нет аналитики по теме → `bank_position = null` и явная неопределённость. RSS недоступен → лента работает на сохранённых новостях.

## Тестирование

- Модульные тесты: новости (RSS-разбор, дедупликация, классификация), лента (смена клиента и роли меняет порядок), проверки агента (верификатор ловит утверждения без источников).
- Сквозной тест через HTTP с тестовым OpenAI-совместимым сервером на `127.0.0.1` (разрешён только при `ALFA_LLM_TEST_ENDPOINT=1`), включая сценарий, где рецензент требует повторный поиск.
- Реальный прогон с ключом организаторов на 3–5 компаниях разных отраслей.
