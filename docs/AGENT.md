# Агентная логика

AI-компонент не делает одиночную генерацию. Для каждого разбора `InsightAgent::analyze` (`src/agent.cpp`) выполняет многошаговый процесс, и каждый шаг попадает в `agent_trace` ответа: `{step, status, decision, detail, duration_ms}`.

| Шаг | Что делает | Модель | Запасной вариант |
|---|---|---|---|
| `plan` | Решает, какие данные нужны: 2–4 поисковых запроса к аналитике Альфа-Банка, нужны ли контрагенты и связанные новости, на чём сфокусироваться для роли пользователя | Gemma 4 26B (`ALFA_LLM_MODEL_FAST`) | Запросы по заголовку, теме события с отраслью и фокусу роли |
| `tools` | Вызывает инструменты: профиль компании (C1), сеть платежей и отрасли контрагентов (P1), связанные новости из ленты (R1–R3), BM25-поиск по аналитике банка по каждому запросу (A1–A6) | — | — |
| `draft` | Пишет разбор в JSON-схеме: что произошло, почему важно, последствия с горизонтом, риски с уверенностью, возможности, действия, позиция банка, выводы модели, неопределённости. Каждое утверждение — с `evidence_ids` | DeepSeek-V4.1-Flash (`ALFA_LLM_MODEL`) | Разбор по правилам, ссылающийся только на N1 и C1 |
| `verify` | Программная проверка (`src/verifier.cpp`): у каждого утверждения есть существующий источник; позиция банка ссылается на A-источник; числа в утверждениях встречаются в источниках; есть «почему важно» и риски или возможности. Затем модель-рецензент оценивает полноту, непротиворечивость и обоснованность и может запросить дополнительный поиск | GLM-5.3-Flash (`ALFA_LLM_MODEL_REVIEW`) | Только программная проверка |
| `revise` | Если проверка нашла проблемы или рецензент вернул `revise`: дополнительный поиск по предложенным запросам (новые A-источники), повторная генерация с явным списком замечаний и предыдущим черновиком, повторная программная проверка. Не больше одного дополнительного круга | DeepSeek | Исходный черновик, неподтверждённые утверждения помечены `supported_by_cited_source=false` |
| `finalize` | Собирает ответ: позиция банка показывается только при ссылке на материал банка; итоги проверки в `quality_check` | — | — |

## Контекст между шагами

Все шаги работают с одним контекстом: профиль компании, роль, план, найденные источники и черновик передаются дальше. Источники нумеруются один раз и не меняют идентификаторы, поэтому ссылки в итоговом разборе совпадают с `sources[]`.

## Разделение фактов, позиции банка и выводов модели

- `facts.what_happened` — что сказано в новости (N1).
- `interpretation.bank_position` — только если модель сослалась на материал Альфа-Банка (A*), иначе `null`.
- `risks`, `opportunities`, `possible_actions`, `potential_effects`, `model_conclusions` — выводы модели, у каждого `source_type` и `evidence_ids`.
- `offers` — предложения продуктов банка с `is_advertising=true`, отдельно от аналитики.

## Уточняющие вопросы

`POST /api/v1/insights/{id}/questions` принимает свободный вопрос и/или разрез `lens`: `risks`, `counterparties`, `treasury`, `scenarios`, `sources`. Модель отвечает только по сохранённому разбору и его источникам; `sources` возвращает список первоисточников без модели.

## Устойчивость

- Ответ модели, который не разбирается как JSON нужной формы, не ломает процесс: шаг получает статус `fallback`, дальше работают правила.
- Исчерпание дневного бюджета даёт статус `budget_exhausted`; модель больше не вызывается до сброса в 03:00 МСК.
- Текст новостей и материалов считается недоверенным: каждый системный промпт запрещает выполнять инструкции из них.
- Неполные данные компании (`data_gaps`) явно передаются модели и показываются пользователю.

## Проверка

`tests/e2e_test.py` запускает агента с локальной тестовой моделью (`tests/mock_llm.py`) и проверяет все ветки: три модели по шагам; доработку по требованию рецензента с двумя вызовами аналитика; битый ответ модели; исчерпанный бюджет; кэш без повторных вызовов.
