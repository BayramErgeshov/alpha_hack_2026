# Безопасность AI-компонентов

| Механизм | Реализация | Где |
|---|---|---|
| Разграничение прав доступа | Bearer-токен `ALFA_API_TOKEN` на все `/api/v1/*` (сравнение за постоянное время). Ключ модели — отдельная переменная, только на сервере, не попадает в ответы, логи и интерфейс | `http_server.cpp`, `main.cpp` |
| Ограничение моделей и шлюзов | Каждый вызов проверяет модель по списку кейса и адрес шлюза по двум разрешённым хостам (HTTPS, без учётных данных, порт 443). Тестовый локальный шлюз доступен только при `ALFA_LLM_TEST_ENDPOINT=1` и только на `127.0.0.1` | `llm_client.cpp` |
| Защита от промпт-инъекций | Текст новостей, страниц и материалов передаётся как данные; системные промпты запрещают выполнять инструкции из них; ответ модели принимается только как JSON заданной схемы, ссылки на неизвестные источники отбрасываются | `agent.cpp` |
| Контроль результата | Программный верификатор: утверждения без источника, позиция банка без материала банка, числа не из источников. Позиция банка показывается только при ссылке на A-источник | `verifier.cpp`, `agent.cpp` |
| Журналирование обращений к инструментам | `agent_trace` в каждом ответе: какие инструменты вызваны, с какими запросами, что найдено, какие модели использованы, сколько длился шаг. Каждый HTTP-запрос пишется в журнал с методом, статусом и временем (без тела и без ключей) | `agent.cpp`, `http_server.cpp` |
| Защита от SSRF | Загрузка страниц и RSS только по публичным http/https-адресам: запрет локальных, частных и служебных сетей, проверка каждого редиректа (до 5), лимит размера ответа | `reader.cpp` |
| Ограничение небезопасных действий | Агент только читает: у него нет инструментов записи, платежей или изменения данных. Источники новостей — фиксированный список изданий | `agent.cpp`, `news.cpp` |
| Ограничение нагрузки и бюджета | Лимит размера запроса (2 МБ), заголовков, длины текста и вопроса; не более 64 одновременных соединений; таймауты; дневной лимит токенов с честным запасным режимом | `http_server.cpp`, `budget.cpp` |
| Чувствительные данные | Данные кейса обезличены; в модель уходит минимальный контекст профиля и агрегаты платежей; персональные данные физлиц не передаются | `agent.cpp` |
| Интерфейс | Без внешних скриптов; весь текст выводится через `textContent` (нет XSS из новостей или ответов модели); ссылки только http/https с `rel="noopener noreferrer"`; раздача статики не выходит за пределы каталога (проверено тестом) | `ui/index.html`, `http_server.cpp` |
| Контейнер | Непривилегированный пользователь, данные только для чтения, порт опубликован на `127.0.0.1` | `Dockerfile`, `docker-compose.yml` |

## Что нужно для продуктивной версии

Аутентификация пользователей через SSO интернет-банка и привязка пользователя к компании (сейчас клиент выбирается вручную); хранение разборов и аудита в БД с ротацией; лимиты на пользователя; отдельный сервисный аккаунт к шлюзу моделей; секреты из хранилища секретов вместо переменных окружения.
