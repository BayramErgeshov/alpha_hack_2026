# Метрики качества и процесс мониторинга

`GET /api/v1/metrics` возвращает текущие значения; состояние сохраняется в `work/metrics.json` и переживает перезапуск.

| Группа | Метрика | Как считается | Цель для пилота |
|---|---|---|---|
| Контент | Доля подтверждённых утверждений `quality.supported_claims_share` | Утверждения со ссылкой на существующий источник / все утверждения | ≥ 0,95 |
| Контент | Доля разборов с позицией банка `quality.bank_position_share` | Разборы, где позиция подтверждена материалом A* | Растёт с пополнением аналитики |
| AI-компонент | Доля доработок `quality.revise_share` | Разборы, где самопроверка потребовала второго круга | 0,1–0,3: ниже — проверка слишком мягкая, выше — слабый промпт |
| AI-компонент | Доля разборов моделью `insights.llm_share` | Разборы через модель / все новые разборы | ≥ 0,9 в рабочее время |
| Персонализация | Полезность `feedback.useful_share` | Оценки «Да» / все оценки | ≥ 0,7 |
| Персонализация | Причины «Нет» `feedback.recent_reasons` | Последние 50 комментариев | Разбор еженедельно |
| Персонализация | Использование по ролям `insights.by_role` | Разборы по ролям | Нет «мёртвых» ролей |
| Эксплуатация | Задержка `latency.avg_ms` | Сумма длительностей шагов агента | < 25 с на разбор |
| Эксплуатация | Бюджет `budget` | Токены за день, по моделям, остаток | Не исчерпывается до 18:00 |

Каждый разбор также содержит `quality_check` (утверждений всего и подтверждено, замечаний до и после доработки, оставшиеся замечания), что позволяет разбирать конкретные случаи.

## Процесс

1. **Ежедневно** — автоматическая проверка: падение `supported_claims_share` ниже 0,9 или рост `revise_share` выше 0,4 — сигнал проверить промпты и источники; расход бюджета по моделям.
2. **Еженедельно** — эксперт Центра макроэкономических исследований оценивает выборку из 20 разборов по шкале: корректность фактов, позиция банка передана верно, глубина интерпретации, применимость действий. Результаты сравниваются с `feedback` пользователей.
3. **При обновлении аналитики банка** — переиндексация, контрольный прогон на эталонном наборе новостей (`data/news/seed.json`), сравнение метрик до и после.
4. **Перед изменением промптов или моделей** — A/B на эталонном наборе: метрики проверки и экспертная оценка должны не ухудшиться.
5. **Обратная связь** — причины «Нет» группируются (нерелевантно, слишком общо, ошибка в фактах, нет действий) и переходят в задачи: правила ленты, промпты, пополнение источников.
