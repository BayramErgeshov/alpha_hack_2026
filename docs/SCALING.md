# Масштабирование и сопровождение

## Новые отрасли
Отраслевые темы — таблица `topic_groups` в `src/feed.cpp` (ключевые слова отрасли по ОКВЭД и ключевые слова новостей). Новая отрасль — одна строка; агент работает с любой отраслью без изменений, потому что получает её название и признаки компании. Следующий шаг — справочник ОКВЭД → темы в конфигурационном файле вместо кода.

## Новые типы клиентов
Порог выручки — параметр `min_revenue` у `/api/v1/clients`; для среднего бизнеса меняется значение и набор ролей (`roles()` в `src/feed.cpp`). Роли задают веса тем новостей и фокус разбора.

## Новые источники данных
- **Новости:** список RSS — `default_news_sources()` в `src/news.cpp`; парсер понимает RSS 2.0 и Atom. Склейка дублей между изданиями работает автоматически.
- **Аналитика банка:** новые PDF кладутся в архив, `scripts/prepare_data.py` извлекает текст постранично с происхождением в `manifest.json`, индекс строится при запуске.
- **Данные о компании:** новые признаки добавляются в `CompanyProfile`, в контекст агента и при необходимости в правила ленты.

## Производительность
Один процесс держит 85 тыс. компаний, 1,4 млн платёжных связей, индекс аналитики и новости в ~130 МБ памяти; лента строится за миллисекунды без модели. Узкое место — вызовы модели: они идут только по клику и кэшируются. Для нагрузки банка: несколько экземпляров за балансировщиком, общий кэш разборов (Redis), очередь заданий для разборов, ночной предрасчёт разборов для топ-новостей по каждому клиенту.

## Техническое сопровождение
- Модули с одной ответственностью: данные (`data_store`), новости (`news`), лента (`feed`), агент (`agent`), проверка (`verifier`), бюджет (`budget`), метрики (`metrics`), HTTP (`http_server`).
- Юнит-тесты на каждый модуль и сквозные тесты через HTTP с тестовой моделью запускаются при каждой сборке Docker-образа.
- Конфигурация только через переменные окружения; состояние в `work/`.
- Ответ API версионируется полем `schema_version`.
