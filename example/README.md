# Примеры работы backend

Папка содержит готовые входные JSON, запросы для ручного запуска и демонстрацию полного сценария: запуск сервера → профиль компании → платёжная сеть → поиск аналитики → два анализа → уточняющий вопрос → ожидаемые ошибки. Новости в примерах синтетические. Результаты показывают работу интеграции и не являются финансовой рекомендацией.

## Запустить сервис и примеры

Из PowerShell в корне проекта:

```powershell
Set-Location '<папка-проекта>'
.\example\start.cmd
```

Команда запускает отдельный экземпляр backend на `http://127.0.0.1:18080`, дожидается готовности и выполняет примеры. После завершения примеров сервер остаётся доступен команде. Для остановки:

```powershell
.\example\stop.cmd
```

Для однократного прогона с остановкой запущенного экземпляра в конце:

```powershell
.\example\run.cmd
```

Порт можно выбрать явно. Параметр должен совпадать при запуске и остановке:

```powershell
.\example\start.cmd -Port 18081
.\example\stop.cmd -Port 18081
```

По умолчанию демонстрация использует локальные данные и текстовые входы; сервер запускается с `-NoLlm`. Платные вызовы модели отключены, даже если в локальном окружении настроен ключ. Сценарий не требует подключения к новостным сайтам. Необязательный пример парсера выполняет внешний запрос только с явным флагом:

```powershell
.\example\run.cmd -IncludeWebExample
```

Этот пример загружает `https://example.com` и сохраняет Markdown в формате, похожем на `r.jina.ai`. Успех внешнего запроса зависит от доступа в интернет, TLS и ответа сайта. Страница `example.com` используется для иллюстрации парсинга и не является банковской аналитикой.

## Что находится в папке

| Файл или папка | Назначение |
| --- | --- |
| `start.cmd` | Запустить demo-сервис, выполнить сценарий и оставить сервис работающим |
| `run.cmd` | Запустить demo-сервис, выполнить сценарий и остановить его |
| `stop.cmd` | Остановить экземпляр, которым управляет demo-запуск на выбранном порту |
| `run.ps1` | Реализация запуска с параметрами `-Port`, `-IncludeWebExample`, `-KeepServer` |
| `client.cpp` | Пример клиента на C++: HTTP-запросы, проверка ответов и сохранение JSON |
| `ExampleClient.vcxproj` | Проект сборки клиента для Visual Studio |
| `bin/AlphaExampleClient.exe` | Готовый клиент, который вызывает скрипт запуска |
| `requests.http` | Запросы для ручного запуска в HTTP-клиенте |
| `requests/` | Входные JSON; их можно редактировать и отправлять собственным клиентом |
| `output/<время-UTC>-<идентификатор>/` | Результаты конкретного прогона: нумерованные ответы API и сведения о выполнении |
| `output/latest.json` | Поля `run_directory` и `summary_file` указывают на последний прогон и его итог |

Сценарий использует готовую сборку backend и данные из основной папки проекта. Если сборки или исходных данных нет, подготовьте их по [руководству запуска](../docs/RUNBOOK.md). Сами примеры не меняют входные CSV и аналитические материалы. Отдельный файл `service.env` задаёт конфигурацию demo-сервера с пустыми полями ключей.

Если этот demo-сервер уже запущен скриптами примеров на выбранном порту, следующий прогон использует его. Занятый другим процессом порт вызывает ошибку. `stop.cmd` останавливает только экземпляр, которым управляют примеры.

В каталоге прогона ответы записываются как `01-health.json`–`12-blocked-local-url.json`; с `-IncludeWebExample` добавляется `13-parse-web.json`. Полный анализ находится в `07-insight-credit.json` и `08-insight-trade.json`, уточнение — в `09-follow-up.json`. `summary.json` содержит общий признак `passed`, `model_call_count=0` и список `scenarios` с ожидаемым и полученным HTTP-статусом, именем файла ответа и признаком успешности. Ожидаемые ответы 400, 404 и 422 считаются успешной демонстрацией обработки ошибки.

Файл `run.json` хранит параметры и время прогона; `output/latest.json` содержит копию сведений последнего запуска. Поле `server_kept_running` фиксирует состояние в момент завершения прогона и не обновляется после отдельного вызова `stop.cmd`.

Пути `run_directory` и `summary_file` сохраняются относительно корня проекта, поэтому сведения о локальном расположении проекта не попадают в отчёт.

Пересобрать клиент можно вместе с `AlphaBackend.sln` (`Release | x64`): результат появится в `example/bin`. CMake также собирает цель `AlphaExampleClient` по умолчанию; параметр `-DALFA_BUILD_EXAMPLES=OFF` отключает её. Для отдельного вызова клиента из PowerShell укажите каталоги явно:

```powershell
.\example\bin\AlphaExampleClient.exe --base-url http://127.0.0.1:18080 --requests-dir .\example\requests --output-dir .\example\output\manual
```

Перед этим запустите `start.cmd`. Отдельный клиент не управляет сервером; повторный запуск в тот же каталог перезапишет одноимённые ответы. Автоматические скрипты создают новый каталог при каждом прогоне.

Клиент проверяет `models.configured=false` до создания анализов и прекращает сценарий, если сервер сообщает о настроенной модели. Его исходник можно использовать как пример интеграции из другого C++-приложения. Скрипты выбирают локальный адрес; клиент принимает только loopback-адреса.

## Что демонстрируется

| Сценарий | На что смотреть |
| --- | --- |
| Готовность и модели | `/health` отвечает 200; `models.configured=false` подтверждает отсутствие ключа в demo-процессе |
| `U_9250` | Профиль строительной компании из синтетического набора, кредитные признаки и агрегаты платежей |
| Поиск аналитики | Фрагмент, имя документа, исходная страница, BM25 score и способ извлечения текста |
| `insight-credit.json` | Связь учебного события о ставках с контекстом `U_9250` |
| `insight-trade.json` | Другой профиль — `U_26030`, оптовая торговля моторным топливом; в данных есть признак ФТС |
| `question.json` | Уточнение по ID анализа, который создан в этом же процессе |
| Ошибочные запросы | 400 для пустого вопроса, 404 для отсутствующей компании, 422 для приватного URL |

Профили берутся из предоставленного набора. `FTS_FLAG` показывает наличие данных ФТС, но не доказывает наличие конкретного действующего контракта. Текст примеров не утверждает, что описанные события произошли. Процентиль выручки относится к компаниям в наборе и не является долей рынка.

При отключённой модели анализ должен вернуть `generation.method="deterministic_fallback"` и `quality_check.llm_used=false`. Это штатный локальный режим на правилах. Follow-up возвращает `method="deterministic_fallback"`: дополнительный содержательный вывод без модели не формируется. Оценка `relevance.score` служит сортировке и не является вероятностью финансового эффекта.

## Для участников команды

**Фронтенд.** Откройте сохранённые JSON в `output`, чтобы собрать карточку компании, состояния загрузки и ошибок, список источников и выводы анализа. Для живых запросов используйте сервер на порту `18080` и [контракт фронтенда](../docs/FRONTEND.md). У backend нет CORS: браузерному приложению нужен proxy. `requests.http` предназначен для HTTP-клиента; поле `@insightId` замените на `id` ответа анализа. При запуске через `start.cmd` созданные ID доступны, пока работает тот же сервер. После `run.cmd` сервер останавливается, а JSON остаются для просмотра; для новых запросов запустите сервер и создайте анализ заново.

**Данные.** Сопоставьте профиль и сеть с CSV, проверьте пропуски и трактовку признаков, затем изучите результаты поиска по банковским документам. Суммы платежей и годовая выручка имеют разный смысл. Правила загрузки и источники описаны в [документации по данным](../docs/DATA.md).

**ИИ.** Используйте два входных JSON как фиксированные сценарии для сравнения. В demo-запуске модель выключена. Для отдельного эксперимента с разрешённой моделью следуйте [инструкции ИИ](../docs/AI.md) и обычному запуску проекта; этот пример специально фиксирует локальный режим, чтобы прогоны не расходовали бюджет. Настройки модели и секреты не передаются в JSON запросов.

## Источники и ограничения результатов

Внутри каждого анализа `N1` обозначает входную новость, `C1` — контекст выбранной компании, `A1`–`A4` — найденные фрагменты банковских материалов. Эти ID действуют только внутри соответствующего ответа. Сопоставляйте `evidence_ids` с `sources`; банковские материалы также перечислены в `bank_analytics`. Наличие найденного фрагмента само по себе не подтверждает вывод и не формирует позицию банка. Локальный режим может вернуть `interpretation.bank_view=null`.

Поиск зависит от подготовленного корпуса `data/analytics`. Результаты могут меняться при замене файлов. У источников со способом `windows_ocr` или `tesseract_ocr` возможны ошибки распознавания чисел, процентов и таблиц: значимые значения сверяйте с исходной страницей PDF. Значение BM25 score не выражает достоверность источника.

Это демонстрационный локальный запуск для команды. Основные настройки, ограничения и работа с токеном доступа описаны в [RUNBOOK](../docs/RUNBOOK.md); описание HTTP-маршрутов — в [openapi.yaml](../openapi.yaml).
