# Alpha News Backend

Backend прототипа новостной аналитики на C++20. Он извлекает основной текст публичной страницы, строит персональный разбор новости для компании из обезличенного набора, ищет подтверждающие фрагменты в аналитике Альфа-Банка и возвращает источники и ход работы агента.

[Общая структура приложения](docs/ARCHITECTURE.md): схема работы, назначение папок, зависимости и требования для backend, frontend, данных и ИИ.

## Быстрый запуск и документация команды

```powershell
Set-Location '<папка-проекта>'
.\start-server.cmd -NoLlm
```

Сервер: `http://127.0.0.1:8080`, проверка: `/health`, остановка в текущем окне: `Ctrl+C`. Для фонового режима: `.\start-server.cmd -NoLlm -Background`; остановка: `.\stop-server.cmd`. Launcher читает локальный `.env`, а `-NoLlm` гарантирует запуск без вызовов модели. Подробности — [RUNBOOK](docs/RUNBOOK.md).

## Возможности

Готовые примеры и запуск сервиса вместе с ними: `.\example\start.cmd` (порт `18080`, без вызовов модели). Для однократного прогона с остановкой: `.\example\run.cmd`. Входные запросы, клиент на C++ и сохранённые ответы описаны в [example/README.md](example/README.md).

- Парсер HTML в стиле `r.jina.ai`: `Title`, `URL Source`, `Published Time`, `Markdown Content`, очистка навигации и рекламы, ссылки, таблицы, изображения и Markdown.
- HTTP API для чтения профиля компании и платежной сети, поиска по аналитике, парсинга новостей, анализа и уточняющих вопросов.
- Персональная релевантность по отрасли, региону, банковским продуктам и агрегированным платежам. Оценка релевантности не является вероятностью финансового эффекта.
- Поиск по аналитическим PDF через BM25 с номером страницы и идентификатором источника.
- OpenAI-compatible вызовы только к двум адресам и шести моделям из инструкции к кейсу. При отсутствии ключа или ошибке модели используется детерминированный разбор.
- Отдельные поля для фактов новости, выводов модели и подтвержденной позиции банка. Позиция банка остаётся пустой, пока ее не подтверждает найденный источник.
- Ограничения входного размера, публичные HTTP(S)-адреса без доступа к локальным сетям, лимит параллельных соединений и токен API через переменную окружения.

## Данные

Для запуска нужны подготовленные файлы:

```text
data/input/df_Uid_data_hack.csv
data/input/df_Uid_payment_hack.csv
data/input/df_Fid_Uid_link_hack.csv
data/analytics/*.md
```

Из корневой папки проекта подготовить их из выданных ZIP-архивов можно так:

```powershell
python -m pip install -r scripts/requirements.txt
python scripts/prepare_data.py .
```

Текст всех девяти документов уже подготовлен: 64 страницы и более 156 тысяч символов находятся в `data/analytics/*.md`. Скрипт сначала читает текстовый слой PDF, а страницы с текстом в виде изображения распознаёт локально. На Windows для этого используется C++-утилита `AlphaPdfOcr.exe` и встроенный движок Windows с русским языком; она входит в решение Visual Studio и уже собрана в `x64/Release`. На Linux предусмотрен Tesseract с языками `rus` и `eng`.

Переподготовить только аналитику, не распаковывая заново CSV:

```powershell
python scripts/prepare_data.py . --analytics-only --ocr windows
```

В `data/analytics/manifest.json` сохраняются исходный документ, SHA-256, способ извлечения и число символов каждой страницы. Непрочитанные страницы помечаются явно, и скрипт сообщает об ошибке. Поиск возвращает `text_extraction` вместе с именем документа и номером страницы; заголовки служебных файлов не считаются банковской аналитикой. OCR может искажать цифры, знаки процента и таблицы, поэтому спорные значения следует сверять со страницей PDF. Внешние ИИ-сервисы для распознавания не вызываются.

## Сборка в Visual Studio

Нужны Visual Studio с C++ workload и установленный `curl` через vcpkg. В PowerShell укажите путь к своему vcpkg, затем откройте `AlphaBackend.sln`:

```powershell
$env:VCPKG_ROOT = '<папка-vcpkg>'
& "$env:VCPKG_ROOT\vcpkg.exe" install curl:x64-windows
```

Собирайте конфигурацию `Release | x64`: решение создаёт backend, локальную C++-утилиту распознавания `AlphaPdfOcr` и клиент `AlphaExampleClient` для демонстрации API. Скрипты запуска сами находят корень проекта; при прямом запуске backend используйте корень проекта, чтобы относительные каталоги данных находились корректно.

Для сборки через CMake:

```powershell
cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE="$env:VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake" -DVCPKG_TARGET_TRIPLET=x64-windows
cmake --build build --config Release
```

На Linux нужны CMake, C++20-компилятор и libcurl. Dockerfile устанавливает эти зависимости самостоятельно.

Тесты индекса собираются CMake и запускаются командой `ctest --test-dir build -C Release --output-on-failure`. Дополнительно `analytics_index_tests data/analytics` проверяет реальный корпус из девяти документов. Проверяются поиск на русском, номера страниц, UTF-8, происхождение текста и исключение служебных заглушек.

## Настройка ИИ

Ключ не хранится в исходниках, `.env.example`, логах или образе. Задайте его только в локальном окружении или локальном `.env`:

```powershell
$env:ALFA_LLM_API_KEY = '<ключ из инструкции>'
$env:ALFA_LLM_BASE_URL = 'https://changellenge.up.railway.app/v1'
$env:ALFA_LLM_MODEL = 'deepseek/deepseek-v4.1-flash'
```

Альтернативный базовый адрес: `https://api.alfahack-gateway26.ru/v1`. Разрешены модели `google/gemma-4-26b-a4b-it`, `z-ai/glm-5.3-flash`, `qwen/qwen3.6-35b-a3b`, `deepseek/deepseek-v4.1-flash`, `qwen/qwen3-vl-30b-a3b-instruct` и `moonshotai/kimi-k2.6`. По умолчанию включена двухэтапная генерация с самопроверкой, поэтому один анализ может сделать два вызова модели. Учитывайте общий дневной лимит организаторов; при необходимости задайте `ALFA_AGENT_SELF_CHECK=0`, чтобы выключить второй вызов.

Для входящего API задайте отдельный `ALFA_API_TOKEN`. Не используйте ключ LLM в качестве токена API.

## Запуск

По умолчанию сервер слушает только `127.0.0.1:8080`. Можно переопределить `ALFA_HOST`, `ALFA_PORT`, `ALFA_DATA_DIR` и `ALFA_ANALYTICS_DIR`.

```powershell
.\start-server.cmd
```

Launcher читает `.env`. При прямом запуске `x64/Release/AlphaBackend.exe` настройки берутся только из окружения процесса; сам C++ executable файл `.env` не читает.

С Docker Compose порт опубликован только на `127.0.0.1:8080`. Перед запуском создайте `.env` из `.env.example`, внесите локальные значения и запустите:

```powershell
docker compose up --build
```

## API

Подробная OpenAPI-спецификация находится в [`openapi.yaml`](openapi.yaml). Основные маршруты:

| Метод и маршрут | Назначение |
|---|---|
| `GET /health` | Состояние сервиса |
| `GET /api/v1/models` | Разрешённые модели и наличие конфигурации ключа (сам ключ не возвращается) |
| `GET /api/v1/companies?q=...` | Точное совпадение UID или кода ОКВЭД |
| `GET /api/v1/companies/{id}` | Профиль и признаки компании |
| `GET /api/v1/companies/{id}/network` | Агрегированные входящие и исходящие платежи и контрагенты |
| `GET /api/v1/analytics/search?q=...` | BM25-поиск по аналитическим материалам |
| `POST /api/v1/parse` | Извлечение страницы и Markdown в формате, близком к Jina Reader |
| `POST /api/v1/insights` | Релевантность и аналитическая интерпретация новости для компании |
| `POST /api/v1/insights/{id}/questions` | Вопрос к сохранённому результату текущего процесса |

Пример разбора новости:

```json
{
  "company_id": "U_9250",
  "url": "https://example.org/news"
}
```

Можно передать `text` и необязательный `title` вместо `url`. Результат содержит `facts`, `bank_analytics`, `interpretation`, `sources`, `agent_trace` и `quality_check`. Ссылки на материалы банка содержат имя документа и номер страницы. Состояние для уточняющих вопросов хранится в памяти и исчезает при перезапуске.

## Ограничения прототипа

- Парсер повторяет формат и основные приемы Reader, но не использует сервис `r.jina.ai` и не обещает идентичный результат для каждой страницы.
- Процентили считаются по предоставленной выборке; рыночную долю из этих данных получить нельзя.
- Платежи агрегированы, без даты и назначения платежа; они не доказывают причинную связь.
- Текст аналитики извлекается или распознаётся локально с сохранением номера страницы и происхождения. Распознавание графиков и таблиц может требовать сверки с PDF.
- Облачный LLM получает текст новости и минимальный контекст профиля/аналитики. Ключ читает только backend из окружения и передает в Authorization header разрешённому шлюзу.
- Для командного/публичного развертывания нужны внешняя аутентификация пользователей, хранение сессий, лимитирование по пользователям и постоянный аудит бюджета.
